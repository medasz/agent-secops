# 内部基础设施清单（ipInfra.md）

> **用途**：失陷主机清单（按 `alarm_sip` 受害方聚合）研判时，识别「基础设施 IP 作为受害方」的误报并剔除。
> **性质**：仅从「失陷主机清单」呈现/解析层剔除，**底层告警数据不动、溯源不丢**。这与 `ipWhite.md`（判定 `sip` 是否外部）是两个独立机制，切勿混用——`ipWhite.md` 含整段私网，若复用于失陷清单会误伤真实内网失陷主机。
> **状态**：示例清单，地址全部使用 RFC 5737 文档保留段。真实基础设施清单属于环境数据，部署时用你的清单覆盖本文件即可。
> **代码**：`scripts/shared/infra-exclude.js`，由 `judgeVictim(alert)` 消费本清单（已确认读取本文件名 `ipInfra.md`）。失陷清单每条受害主机同时输出 `风险描述`（复用 ban-ip-table 的 `attack-type-mapping.json`，与封禁建议表口径一致）与 `研判意见`。

## 研判逻辑（基于「攻击成功/失陷」主机特征，按协议特征研判，非白名单忽视）

`judgeVictim(alert)` 对每条 `host_state ∈ {攻击成功, 失陷}` 告警研判真实受害方（`alarm_sip`，缺失兜底 `dip`），**仅按特征判定是否剔除，绝不忽视告警信息**：

1. **受害方取 `alarm_sip`**（IDS 判定的被攻击方 / 被控内网主机本身）；`alarm_sip` 缺失时兜底 `dip`，避免漏统。
2. **协议 = DNS 且 `alarm_sip` 命中本清单（基础设施）** → 判定为 **「DNS 转发设备出向查询被 IDS 误标」**，从失陷主机清单**剔除该转发设备**（底层告警 / ban-domain 数据保留，不忽视）。
   - 误报机理：内网主机 → 基础设施 出向查询，IDS 用「远控木马/窃密木马」特征规则把这类流量误标为 `host_state=失陷`，并把**发起方（基础设施自身）**写成 `alarm_sip`（受害方）。证据链：`真实 sip == alarm_sip == 基础设施自身`，`dip` 为正常 DNS 服务器，**零 C2**。
   - 说明：单条告警中并无独立「真实发起查询主机 IP」，IDS 已把转发设备自身写成 `alarm_sip`，单条层面无法还原发起方，故仅剔除转发设备、不虚构受害 IP。
3. **协议 ≠ DNS 且 `alarm_sip` 命中本清单** → **不盲目剔除**（可能是真实被打基础设施），保留为受害主机，附 `风险描述` + `研判意见`，提示人工复核是否真失陷。
4. **其余（`alarm_sip` 非基础设施，或 DNS 但非基础设施）** → 真实受害主机，附 `风险描述` + `研判意见`，正常输出。

> **为何不一刀切整 IP 加白 / 不一刀切当白名单忽视**：整 IP 加白会掩盖「真实被控基础设施」情形，且抹掉底层告警丢失溯源。本清单只做「DNS 转发设备误标」的精准剔除，告警本身保留，可交 IDS 同事从探测配置根治。
